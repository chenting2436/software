# 矿大土行孙 V2：甲方演示改造规划

> 历史规划：后续用户已明确取消固定九宫格，增加四大模块、三类独立设备与数据回溯。最新规则和实际交付状态以《V2.1产品改造交付说明.md》为准。

日期：2026-09-21。本文是下一阶段改造方案；除九宫格排版规则外，以下内容均为拟建设目标，不代表当前版本已完成。

## 1. 交付目标与现状判断

演示目标：让甲方能够从一个真实业务问题出发，连续查看设备、数据、算法、预警和报告，并理解每项能力的实施范围。演示数据保持离线、可复现，前端角色切换沿用已确认范围。

当前代码已经提供 130 个组件入口与 31 项算法入口，但入口数量不等于业务完成度。目前影响可信度的具体问题是：

- 多种业务模块共享相同的表格结构、示例行和统计指标，字段与具体业务并不总是对应。
- 算法页面大多共享相同参数，图表按通用样式生成，没有充分表达各算法输入、处理和成果的差异。
- 部分“新建、配置、导出”操作只产生提示文字；部分成果和版本按钮没有对应详情。
- 角色切换主要改变角色名称，尚未完整联动页面、按钮和项目数据范围。
- 小字号、重复指标、过多描边与装饰性光效削弱了信息层级；完整页面塞入小组件后，阅读和操作都很拥挤。

下一阶段以业务深度、数据一致性和交互完成度为验收依据。现有组件清单保留，每一项重新建立“入口—工作台—具体记录—操作结果”的对应关系。

## 2. 已修改的九宫格规则

- 每屏固定 3 行 × 3 列，最多 9 个模块，每个模块占一格，尺寸相同，禁止单独缩放。
- 适配屏幕时整组等比例/等分调整；“固定大小”指同屏等大，不是为所有显示器锁死相同像素值。
- 支持组件库拖入空位、点击添加、拖动交换位置、下拉选择位置；每个组件同屏最多出现一次。
- 未使用的格位保留；移除模块不导致其他模块自动补位。
- 地图、设备状态仍在默认布局中，允许移除后重新添加。
- 第 10 个模块无法添加，界面明确显示容量与剩余位置。
- 设计器、预览和重新打开后的布局使用同一组位置数据。
- 旧版自由布局按从上到下、从左到右转换，最多取前 9 项；旧存储记录保留，新九宫格布局独立保存。

## 3. 产品结构：总览、工作台、具体记录

| 层级 | 用户看到什么 | 用户能做什么 |
| --- | --- | --- |
| 九宫格总览 | 每格一个模块，展示核心状态、最新异常、最近成果与更新时间 | 扫视风险、选择对象、打开完整工作台 |
| 完整工作台 | 当前模块对应的表格、地图、波形、剖面或任务管理页面 | 筛选、切换时间、修改参数、创建任务、处置事件 |
| 记录/成果详情 | 明确的设备编号、数据批次、任务、参数版本、结果或报告 | 追溯来源、比较结果、查看日志、保存与导出 |

设备台账和账号管理继续作为整页业务模块加入大屏。模块采用适合九宫格的紧凑布局，展开后进入同一业务页面的完整视图，保持选中的对象、筛选条件和任务上下文。避免把完整桌面页面按比例缩成难以辨认的小图。

建议准备“综合监测、设备与数据、主动源、被动源、微震、风险处置”场景模板；每个模板都遵循九宫格容量。模板是演示配置，用户仍能自由替换其中任意模块。

建议的综合监测模板：

| 左列 | 中列 | 右列 |
| --- | --- | --- |
| 设备在线与异常 | 数据回传与质量 | 最新预警事件 |
| GNSS 位移趋势 | 矿区地图 | 微震空间分布 |
| 算法任务与成果 | 处置任务 | 报告与归档 |

地图与其余八格等大。打开地图工作台时再提供大幅空间视图。

## 4. 视觉方向：克制、专业、可读

沿用用户给定的矿大配色：主色 #1B58A1，辅助色 #91AECF、#BCD7F5、#D8E4F0，正文接近 #090911。

工作台采用浅灰蓝背景、白色内容面板、深色文字；大屏采用低饱和深蓝背景，风险颜色单独表达业务等级。二者统一字号、图标、间距和状态语义。

- 减少大面积渐变、发光边框、重复小徽章和英文宣传标题。大标题改为项目、区域、时间与业务名称。
- 以 1920×1080 为主要验收尺寸，兼顾当前演示窗口；业务正文建议 13–14px，表格正文不低于 12px，重要数值 20–28px。
- 模块内容采用清晰的“标题/时间—核心状态—图表或列表—操作入口”顺序。空间不够时使用紧凑摘要和详情入口，避免无限缩小字体。
- 图表标注单位、坐标、图例、时间范围和来源；颜色、精度、单位在全系统一致。
- 控件按用途选择：事件用时间线，设备用档案和状态表，波形用多道工作区，地图用空间选择，权限用矩阵。
- 正常界面显示业务语言，如“查看设备”“参数配置”“结果对比”；统一保留低干扰的“演示数据”标识。可重复演示的控制按钮放在演示控制面板中。
- 动效用于选中反馈、任务推进和时间回放，避免随机数不断跳动或长时间装饰动画。

## 5. 一套连贯的演示项目

建立“矿大示范矿区”离线样例：北帮、南帮、东帮等区域，共用设备台账、测点、通道、坐标、采样率和时间轴。统计值由同一份样例数据计算。

对象关系为：项目 → 区域 → 测点 → 设备/通道 → 数据批次 → 算法任务 → 结果 → 风险事件 → 处置 → 报告。

至少准备三套可重复场景：

1. 正常运行：设备回传、质量检查、定时分析、日常报告。
2. 掉线与恢复：指定设备心跳中断，显示最后报文和时间空窗；恢复后展示补传、质量变化与处理记录。掉线不会直接等同于边坡风险。
3. 风险闭环：北帮位移变化，联动相关微震和降雨样例，完成数据质量复核、算法对比、风险研判、派单、现场反馈、复核与报告。

回放支持暂停、继续、倍速和重置场景。每次操作产生可追溯记录，重新打开仍保留当前演示进度。明确区分“本地持久化配置”与“可重置的场景数据”。

## 6. 业务模块的改造标准

| 模块 | 完整页面应包含 | 必须产生的交互结果 |
| --- | --- | --- |
| 设备台账 | 项目/区域树、分类筛选、分页、设备档案、通信/供电/通道/维护页签 | 筛选改变列表；选中设备联动地图；编辑后刷新档案与统计；导出当前筛选结果 |
| 设备状态 | 心跳时间、最后回传、离线时长、供电、网络、故障原因 | 查看离线设备并进入通信记录；触发演示重连后状态和时间线更新 |
| 地图 | 区域边界、台阶/等高线、测点、设备类型图层、风险区域、图例和比例尺 | 点选设备联动档案；框选区域过滤数据；时间回放改变事件分布；二维/三维视图保持当前对象 |
| 数据中心 | 回传拓扑、原始报文、字段映射、标准数据、质量问题、隔离重放 | 点选一条报文可追踪处理节点；修改演示映射并重放后显示前后差异与结果 |
| 算法任务 | 专业输入、参数约束、任务队列、中间成果、结果和质量控制 | 输入或参数改变后生成对应的演示结果版本；支持取消/失败/重试与历史对比 |
| 风险事件 | 规则命中、数据质量、算法证据、置信说明、责任人与处置时限 | 确认、派发、反馈、复核、关闭改变真实前端状态；保留操作人、时间和原因 |
| 账号权限 | 账号列表、角色矩阵、项目范围、启停、操作记录 | 前端角色切换改变可见操作和数据范围；访客禁用编辑；账号表单保存后反映在列表 |
| 配置运维 | 协议版本、配置差异、发布流程、服务依赖、资源和故障记录 | 演示灰度、失败和回滚改变版本状态并形成操作记录 |
| 客户方案 | 已选功能、依赖、实施边界、交付清单、方案预览 | 选择变化同步方案；导出实际生成的文件，不仅提示“导出成功” |
| 闭环报告 | 项目信息、事件时序、证据图表、算法版本、处置记录、复核结论 | 根据当前事件生成预览、打印/导出；结果与大屏和事件详情一致 |

地图可使用内置示意地形和样例坐标满足离线演示。真实矿区测绘底图需要后续提供，并明确来源；当前样例不冒充现场实测资料。

## 7. 31 项算法逐项深化

共用任务管理外壳，内部专业页面按算法设计。每项都包含输入选择、专用参数、处理中间结果、成果查看、质量评价、任务与版本追踪。单位、参数名称与具体算法一一对应。

以下属于交互与展示设计，计算结果采用可追溯的离线样例或预设工况；涉及工程结论的阈值和计算有效性在真实开发阶段由专业人员确认。

## 8. 关键交互完成的定义

- 搜索真的筛选数据；时间范围真的改变图表和统计。
- 新建/编辑提供字段、校验、取消与保存，保存后列表和详情同步。
- 算法参数有适用范围、单位和依赖；可选预设与离线成果明确对应。
- 同一次任务在任务列表、成果中心、预警证据和报告中使用同一编号。
- 导出生成实际文件，内容对应当前选择。
- 失败、空数据、运行中、取消、重试都有界面，且任务状态保持一致。
- 回退到列表或关闭详情保持原筛选和位置。
- 角色差异作用于菜单、按钮和演示数据范围，仍明确属于前端演示权限。
- 控件有明确业务用途；没有作用的装饰元素不做成可点击按钮。

## 9. 新增相关能力的建议

优先把以下能力纳入组件库，并与已有业务关联：值班交接、巡检工单、设备校准记录、监测覆盖盲区、事件时间回放、数据质量专题、成果版本对比、项目验收清单。上线前先检查已有组件是否覆盖，避免同一能力换名重复增加数量。

这些组件也遵循同一九宫格规则，并能追溯到设备、任务、事件和报告。

## 10. 甲方演示脚本（约 10 分钟）

| 环节 | 现场动作 | 甲方看到的价值 |
| --- | --- | --- |
| 1 分钟：总体态势 | 打开综合九宫格、介绍区域和当前异常 | 项目范围与运行状态清楚 |
| 2 分钟：设备与数据 | 从地图选中设备，查看档案、掉线与补传、报文和质量 | 设备管理与数据治理是完整链路 |
| 3 分钟：算法分析 | 打开一个重点任务，检查波形/参数、比较成果、展示另一个算法家族 | 不同算法具备不同操作与成果，专业深度可见 |
| 2 分钟：风险闭环 | 查看证据、确认风险、派发、反馈、复核 | 异常能进入有责任人的处置流程 |
| 1 分钟：报告与方案 | 生成事件报告，切换客户方案的能力清单 | 能形成可交付的业务结果 |
| 1 分钟：配置与角色 | 切换访客角色，交换一个大屏模块，保存预览 | 可配置、可分权、可按客户交付 |

另备三个问题的自由演示入口：“这个数据从哪来”“参数改了有什么变化”“这次预警为什么产生”。回答均能沿当前记录继续钻取。

## 11. 实施顺序与每轮交付

| 阶段 | 交付内容 | 完成门槛 |
| --- | --- | --- |
| 0：排版规则 | 固定九宫格、限额、拖动、删除、保存恢复 | 同屏等大、最大 9 项、预览一致；本轮已实施 |
| 1：高保真样板 | 九宫格视觉样板、设备台账/详情、地图、微震定位工作台、闭环报告样板 | 先建立一套可见、可操作的质量基准；用户看过效果后用于其他模块 |
| 2：业务闭环 | 共用样例项目、设备—数据—算法—风险—报告联动、角色效果 | 至少两条完整场景能从头演示到导出 |
| 3：全量算法 | 31 项专属输入、参数、专业成果、质量与版本 | 每项至少 3 个有业务结果的专业操作，并能追溯输入与任务 |
| 4：其余业务组件 | 逐项替换通用占位表格，补齐相关模块 | 覆盖清单中每项均有独立业务字段和可验证操作 |
| 5：交付验收 | 演示脚本、功能覆盖表、EXE/安装包、离线资源、样例重置 | 断网启动、配置保存、重启恢复、全过程演示通过 |

第一轮建议优先以“设备台账 + 地图 + 微震精细定位”建立业务和视觉基准，并用九宫格、报告样板检验整体风格。后续仍覆盖全部 31 项算法和已确认组件，不以样板替代全量范围。

## 12. 验收清单

1. 排版：9 个等大格位，添加、移除、交换、保存、重新打开与预览一致。
2. 可读：1920×1080 演示时单位、状态和表格可读，工作台不会用极小字号塞内容。
3. 专业：31 项算法在输入、参数、专业图形与关键操作上有可解释差异。
4. 一致：设备数、在线数、事件数等来自同一数据集合，时间和对象编号可连续追溯。
5. 交互：不存在点击后仅提示“已打开”却没有页面、表单或状态变化的核心按钮。
6. 角色：角色切换后可见动作、只读限制和项目范围有实际变化。
7. 报告：从当前事件生成，含正确证据、参数版本、处置与复核记录。
8. 演示：离线完成预设脚本，并能处理自由点击、返回、重试和重置。
9. 覆盖：提供逐项表，注明“已完成交互演示/待深化/真实开发工作包”，不把入口数当作已实现功能数。

## 13. 本次边界

当前已实施的是固定九宫格及相关保存/拖拽规则。本文中的视觉重做、真实前端业务状态、31 项算法专属工作区等需要按阶段继续开发；当前九宫格里的业务内容仍是上一版演示内容。完整业务重做先按本规划供用户审阅。
